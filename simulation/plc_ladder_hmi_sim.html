Press START on the HMI. Up to five products are on the line at once. Press E-STOP (or open the E-stop chain) and everything stops; RESET and START bring it back. Switch on a fault to see the alarm, switch it off, then RESET and START. Product B is the defective one, and the camera result (X11, X12) decides where the robot puts it.

Live values of every device. Force a field input to 0 or 1 to test the logic, then set it back to Auto so the virtual plant drives it again.

Run it on OpenPLC

  1. Open the OpenPLC Runtime web page (usually http://localhost:8080), go to Programs and choose Upload program. Select SmartTextile.st, or save the code on this page into a file with that name.
  2. Press Launch program. The runtime compiles it with matiec; this takes about a minute.
  3. Open Settings, tick Enable Modbus Server (port 502) and save.
  4. On the dashboard press Start PLC.
  5. Connect a Modbus TCP client. Write coil 800 to start the machine and coil 808 for the HMI emergency stop, read coils 0 to 11 for the outputs and holding registers 1024 to 1033 for the counts and KPIs. The table below lists every address. The easiest way to drive the sensors is the plant_sim.py script.
Simulation profile: the field inputs X0 to X20 are coils 816 to 832, so a Modbus client or plant simulator can act as the sensors and the vision system. At power-up X16 and X17 read 0, so the PLC starts with a latched E-stop and fault; press RESET once the plant script is connected. Switch to the hardware profile to map them to real %IX inputs. Some clients count addresses from 1, so try address + 1 if coil 800 does not respond.
The runtime executes this Structured Text program. The ladder drawings on the Ladder tab are the same logic and are the reference if you draw the rungs yourself in OpenPLC Editor.
